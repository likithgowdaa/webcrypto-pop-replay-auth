Educational Security Architecture & Defense Analysis

        Theory & Viva Preparation
      


      

        

          
The Central Problem: Stolen Bearer Tokens

          

            In ordinary bearer-token authentication (OAuth2 / standard JWT), the bearer token acts like physical cash. If an attacker intercepts the token via server logs, network eavesdropping, or proxy inspection, the attacker can impersonate the user from any machine.
          

        


        

          
The Solution: Proof-of-Possession (PoP)

          

            Proof-of-Possession cryptographically binds the bearer token to an asymmetric ECDSA P-256 key pair. The private key remains non-extractable in the owner's browser. The server verifies that each request is signed by the exact private key corresponding to the session's registered public key.
          

        


        

          
Why Attacker Key Forgery Fails (Attack 2)

          

            Even if an attacker possesses the stolen bearer token and generates their own valid ECDSA private key to sign the request, the backend checks the signature against the Owner's registered public key stored in the session table. Verification fails with 401 SIGNATURE_INVALID.
          

        


        

          
Replay Prevention: Timestamp + Nonce Cache

          

            If an attacker captures the owner's exact signed request and re-transmits it (Attack 3), the server rejects it with 409 REPLAY_DETECTED because the unique proof identifier (nonce) is recorded in an atomic single-process cache with a 60-second sliding window.
